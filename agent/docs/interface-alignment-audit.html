04 · CLOSED BLOCKERS

修复前 P0：现已全部关闭

以下内容保留为问题复盘；对应修复与正反例测试已经进入当前工作树和全量门禁。

P0

合法 Command 响应会被 Godot 严格校验器拒绝

command.schema.json 和 TypeScript 均强制要求正整数 revision，但 Godot validate_command_result() 的封闭字段表遗漏该字段。由于 _require_shape 会拒绝额外字段，符合 Schema 的后端响应反而被判为 LOCAL_CONTRACT_RESPONSE_INVALID。

  • 测试 fixture 同样遗漏 revision，因此 Validator 和测试同时写错时仍显示通过。
  • 修复：加入字段与范围校验，并自动比较 JSON Schema 的 required 与 Godot 严格字段表。
P0

当前 HTTP attempt 与命令原始上下文被混为一体

公开 OpenAPI 没有请求 X-Trace-Id 或完整 correlation/content context，但 Gateway 强制响应头和响应体七个上下文字段都与本次调用一致。Command 资源又保存创建时的原始上下文，正常轮询使用新 ID 时必然冲突。

POST A创建 Command，并保存原始上下文 A。
GET B新 HTTP attempt 使用请求/Trace B。
错误比较Gateway 用 B 去比较 Command 中的 A。

修复：响应头/meta 只表示当前 attempt；资源中改为 origin_context，不再与当前 GET 完整比较。必须新增 POST A → GET B 测试。

P0

Agent 反馈与 fallback 没有公开 Wire 承载

Backend 承诺输出 degraded/source/fallback_reason，Frontend 要求展示解释、反馈和降级状态；但 Command、Run 与 AsyncAPI 都是封闭 Schema，且没有 agent.* 下行事件。内部 LlmReply 字段无法自动成为公开协议。

修复：新增版本化 AgentTurnOutcome/AgentFeedback DTO，或增加 agent.turn.completed 事件，并把反馈、降级、证据引用写入同一个可验证 Schema。

05 · CLOSED HIGH PRIORITY

修复前 P1：Agent 范围内已关闭

WebSocket、异步 Transport、UNKNOWN 对账、状态机、鉴权 profile 和不可变 Manifest 均已实现；消费者仓库只需锁定并实现该发布。

P1

WebSocket 仅有事件模型，没有连接协议

Bootstrap 没有明确 stream_id；AsyncAPI 没有 server/protocol/security/binding/握手/订阅帧/resume cursor/心跳/close code。不同团队可各自“正确”地实现出互不兼容的协议。

P1

Godot Transport 仍是同步接口

execute() 立即返回 Dictionary，不能自然表达 Godot 异步 HTTP 的完成信号、超时、取消和重连。生产 Transport 实现前应改为 awaitable/signal 驱动结果。

P1

命令终态与 202 描述不完整

Backend 文档漏掉 UNKNOWN；它是终态不确定性，只能继续按原 command_id 对账，不能换新幂等键。公开返回 202 的实际是 Build、Activation、Session、Turn、Client Events 五个 POST，而不是“认证/运行/世界提交”内部阶段。

P1

Godot 事件语义校验不足

客户端只检查 command 状态是否在枚举内，没有完整检查合法状态边；Skill Activation 与 Learner Model 的 revision 只验范围，没有验证严格 previous + 1，错误事件可能静默进入 UI/store。

P1

开发鉴权存在三套约定

OpenAPI 标注 JWT，文档使用 student-dev/admin-dev，Mock 使用 <tenant>:<actor>。需要固定 dev/prod 两个 profile，并给出精确 token 格式、actor 映射和角色权限。

P1

消费者没有锁定同一契约发布

Backend/Frontend 未使用 submodule、包锁、release manifest 或 SHA。必须让两个仓库的 CI 固定同一个 Agent Wire Contract Release。

06 · TARGET CONTRACT

建议统一的 Wire 规则

1. 明确区分当前请求与资源原始上下文

{
  "meta": {
    "request_id": "req_current_attempt",
    "trace_id": "trace_current_attempt",
    "correlation_id": "corr_business_flow",
    "schema_version": "1.0.0"
  },
  "data": {
    "command_id": "cmd_...",
    "revision": 3,
    "origin_context": {
      "request_id": "req_original_post",
      "trace_id": "trace_original_command"
    }
  }
}

2. 为 Agent Feedback 增加公开 DTO

{
  "feedback_id": "feedback_...",
  "turn_id": "turn_...",
  "message_key": "agent.turn.summary",
  "message": "已根据认证 Skill 完成浇水操作。",
  "source": "provider | provider_fallback | policy",
  "degraded": false,
  "fallback_reason": null,
  "evidence_refs": []
}

3. 把 WebSocket 从 prose 升级为机器合同

  • Bootstrap 返回明确的 stream_id、stream_url、协议版本及最后确认 sequence。
  • AsyncAPI 增加 servers、wss protocol、Bearer security 与 WebSocket binding。
  • 固定订阅/恢复帧：stream、after_sequence、heartbeat、ack、error、close code。
  • HTTP backfill 和实时 WS 使用同一封闭事件 union，避免回放能出现实时客户端不认识的 payload。

07 · AUTOMATED GATES

防静默 bug 的自动化门禁

这些门禁均已落地并进入 scripts/verify-all.ps1；任何字段漂移、错误身份、证据篡改、非法 revision、清单漂移或 Godot 边界退化都会让验证非零退出。

  • Schema ↔ Godot 字段一致性：自动比较所有 strict DTO 的 required/properties 与 Validator 字段表。
  • POST A → GET B：每次 HTTP attempt 使用新 request/trace，验证 origin context 不与当前 attempt 混淆。
  • 真实消费者合同测试：FastAPI 测试服务 + 生产 Godot HTTP Transport，不只测试内存 Mock。
  • 幂等回放：同 key 同 body 回放原 receipt；同 key 异 body 必须 409；检查 Idempotency-Replayed。
  • 状态机负例：拒绝同态跳转、跳级、终态回退及非法 UNKNOWN 重试。
  • revision 负例：World、Registry、Learner 的新 revision 必须严格 previous + 1。
  • Agent 降级 E2E：provider 失败后，合法 feedback DTO 到达前端并明确展示 degraded。
  • WebSocket 恢复：重复、乱序、缺口、断线、过期 token、跨 tenant 订阅和 HTTP backfill。
  • 消费者版本门禁：Backend/Frontend CI 校验同一 manifest SHA，不匹配立即失败。
