# 本次对话漏检复盘与八模块验收清单

本项目是 Demo，只检查真实功能、状态一致性和响应速度，不引入生产级防御架构。测试结果另记在本目录的 modules-audit 报告和原始日志中。

## 我之前检查不足的地方

| 漏检或判断错误 | 为什么原检查发现不了 | 以后必须验证的操作 |
| --- | --- | --- |
| 失败后连续聊天，历史读取膨胀到 13,546 条 SQL、约 34 秒 | 单次读取、短历史测试不能证明连续使用成本；递归校验在历史关联中重复展开 | 先失败，再连续问答，再读列表；记录 SQL 数和耗时，检查新请求仍读到新状态 |
| 正确代码也等待数分钟 | 只看最终任务完成，没有分开编译、运行可见、反馈、成长总结；忽略重复 Worker 处理 | 记录各阶段时间；运行完成应先可见，问叮当不必等待 Book 和学习投影 |
| 改代码后 Bug Agent 不触发 | 重复运行同一技能版本的测试绕过了真实“修改—编译新版本—运行”流程 | 同一技能修改三版后连续失败，检查计数 1/2/3 和角色；成功后再失败应重新计数 |
| 工作区并发读写偶发 500 | 所有读写串行，没让保存草稿发生在一次多表读取中间 | 真实数据库事务交错，验证当前请求快照一致，下次请求可见更新 |
| 文字问答缺失历史 | 能收到回答被当作“聊天已接通”；没有检查第二轮传给模型的上下文 | 第二轮应含第一轮问题和回答，当前问题不重复进入历史 |
| Hint 与 learner 发布抢消息序号 | 分别测试两条链路，都通过；没有把两者交错运行 | Book 交接后先完成 Hint，再执行学习投影，随后历史、Run、workspace 都应可读 |
| 编译错误只有通用 COMPILE_ERROR，具体原因丢失 | 测试用不同错误代码代替真实编译器输出；读取到错误码就认为详情存在 | 用缺分号、未声明变量等不同诊断，检查保存、上下文、历史以及公共接口兼容 |
| 把不同编译错误累计触发 Bug 误判为问题 | 没先对齐你的教学需求，套用了“同一错误才累计”的假设 | 不同编译错误允许累计，历史错误详情要保留；本次只有一个题目，不扩展跨题需求 |
| 问叮当实时语音与教学分层分离 | 语音连通、文字教学通过，不等于两者行为一致 | 语音读取同一教学策略、失败计数、最新编译和运行状态；重复提问不增加错误次数 |
| 对“全接通”的结论说得过满 | 模型配置、模拟依赖测试、真实外部调用、前端联调混在一起 | 每项标注依赖和实际覆盖边界；失败及未验证项保留，不能用总通过数覆盖 |

后续在此项目内复查时，直接沿用这份清单；先跑连续操作和模块交错场景，再给出功能是否接通的结论。

## 本轮八模块检查标准

| 模块 | 必查行为与衔接 |
| --- | --- |
| 1 学生与会话 | 初始信息、创建/读取会话、工作区恢复、已存在会话重入 |
| 2 内容与草稿 | 任务内容、保存/读取、版本变更、并发保存后的读取 |
| 3 编译与激活 | 接收提交、真实 Docker 编译、拒绝详情、结果读取、激活新版本 |
| 4 执行与世界 | 真实沙箱执行、成功/失败、世界提交、评分、证据与事件、重试不重复提交 |
| 5 调度与反馈 | 上下文、模型、跨技能版本错误计数、角色、恢复、连续历史读取成本 |
| 6 提问与建议 | 多轮历史、最新状态、分级提示、生成补丁、接受/拒绝和持久化 |
| 7 实时语音 | 真实豆包音频输入输出、文字、连续两轮、上下文变更、打断、关闭；区分模拟协议测试与真实验证 |
| 8 学习与成长 | 成功/失败更新、知识点、Book 总结、Hint 穿插、投影与总结只保存一次 |

正式游戏数据不写入测试任务；使用独立数据库。性能实测与大批回归分开运行，避免把测试竞争造成的耗时当作产品回归。
