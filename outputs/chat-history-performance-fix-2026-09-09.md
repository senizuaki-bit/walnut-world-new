# 连续聊天历史读取性能修复

2026-09-09。修复“失败运行后连续聊天，列表读取递归重复校验历史”的问题。

## 原因与改动

每条聊天会回溯前面的 Hint 和失败 Run；回溯再次进入同一套历史校验，而 Hint 没有共享校验结果，Run 校验状态也在递归中重新创建。5 轮聊天因此触发 31 次 Hint 完整校验和 13,546 条 SQL。

复用现有 `TerminalProjectionValidationState`，在一次读取内贯通列表、Hint、历史 Hint 和失败后缀校验。每条 Hint 完整验证成功后复用结果，相关 Run 使用同一份校验状态。状态限定在当前请求的数据库会话内，下一请求重新验证。

业务代码仅涉及：

- `walnut-world-backend/src/walnut_backend/adapters/postgres/product_interactions.py`
- `walnut-world-backend/src/walnut_backend/adapters/postgres/run_outcomes.py`

没有增加缓存服务、修改数据库结构或变更前端接口。

## 验证

相关测试共 36 项通过：

- 新增 `tests/integration/test_chat_history_query_budget.py` 的 2 轮、5 轮场景：完整列表、仅最新一页、单条读取均验证每条历史只完整校验一次，并限制 SQL 数量。
- 新请求仍会发现页外历史内容及失败 Run 的 Evidence 被改坏，恢复数据后正常读取。
- 原有 Hint、终态校验复用、失败尝试恢复及上下文 Run 依据测试共 34 项通过。
- 修改文件的 Ruff 检查通过，独立代码审查未发现问题。

新增测试在修复前的 2 轮场景明确失败：1,403 条 SQL、3 次 Hint 校验；修复后为 556 条 SQL、2 次 Hint 校验。

仍保留前序历史读取和现有完整校验，没有针对超长历史扩大优化范围。本次验证覆盖上述本地场景，不代表真实模型响应耗时。
