# Agent 短等待与重复读取优化

本轮只修改后端，保留前端接口。目标是减少模型短时间 PENDING 引起的整轮恢复，以及 Agent 读取中的重复 SQL。

## 改动

- `PostgresDurableLlm` 增加可选短等待。提交链路 ROOT、FINAL 最多等待 6 秒，并受请求超时的一半约束；按服务端 Retry-After 查询原 dispatch，不重新发起模型生成。等待期间不持有数据库事务；查询卡住或超过预算时，继续走原有持久化恢复流程。
- `PostgresAgentRuntimeReads` 的 15 个读取方法使用已有 `snapshot_read`，在一次读取事务内复用相同 SQL 和参数的结果。缓存随事务释放，下一次读取仍读取新状态；写入 Agent trace 的方法保持原样。
- 新增真实 PostgreSQL 集成测试，覆盖短等待成功、等待预算不足、查询挂起超时、恢复及已完成结果重读，断言仅生成一次模型请求。

## 独立真实复测

真实 Godot 客户端、Docker 编译/执行、DS 模型；在原数据库副本上连续修改代码并提交三个技能版本。复测期间没有并行运行回归测试。

| 轮次 | 上轮提交至回复 | 本轮提交至回复 | Worker 次数（前→后） | Worker SQL（前→后） |
| --- | ---: | ---: | ---: | ---: |
| Teaching 1 | 54 秒 | 53 秒 | 5→1 | 10,309→4,280 |
| Teaching 2 | 58 秒 | 47 秒 | 5→1 | 10,963→4,800 |
| Bug 3 | 64 秒 | 53 秒 | 5→1 | 13,417→5,585 |

Bug 轮客户端等待减少 11 秒（约 17%），Worker SQL 减少约 58%。Bug 上下文仍只构建一次，耗时由 4.875 秒变为 1.313 秒，SQL 由 2,633 变为 499。

三轮 Worker 耗时为 21.813、20.375、20.906 秒，现在包含本轮内的模型等待；旧 Worker 计时不包含大部分跨轮等待，因此不能直接当作纯计算耗时对比。每轮均有 4 次真实模型请求，分别合计约 5.000、5.842、5.310 秒。此结果是各一次真实样本，模型和 Docker 有波动，不是稳定性能保证。

先前与回归测试同时运行的样本为 66、68、81 秒，保存在 `bug-fast-wait-*`，不能用于宣称加速；上表采用后续独立复测 `bug-fast-wait-isolated-*`。两组都保留供核对。
