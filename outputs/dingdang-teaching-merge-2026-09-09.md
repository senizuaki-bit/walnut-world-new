# 问叮当统一教学辅导

教学辅导作为问叮当的能力接入。文字 Agent 与游戏内豆包语音共用 PedagogyPolicy：依据当前题目的正式失败次数、错误证据和学习档案计算教学阶段、提示等级。语音无需另调 DS，也不因多聊一轮增加失败次数。

内部 teaching_agent 标识继续供旧文字接口、自动反馈和历史数据使用；没有迁移历史记录或删除角色。小核桃执行、Bug 排错、Book 总结的原有 DS 工作流保持兼容。前端语音接口路径和消息协议没有变化，仍需完成前端麦克风联调。

## 后端行为

- 编译失败使用已有构建计数和已保留的诊断正文；给模型提供当前错误及最近六次历史摘要。
- 运行失败复用 OUTCOME_DERIVED 回执中的计数，不递归重算整段历史。回执未生成时注明计数待整理。
- 学习档案参与同一教学策略的阶段选择；提示等级受到关卡上限限制。语音不会批准或应用代码修改。
- 每秒一次 SQL 检查 Run、构建状态、结果回执和学习档案变化；状态不变就不重新读取完整上下文。
- 输出仍由豆包语音模型生成，教学规则以提示词传递，不具有 DS 结构化输出逐句校验的保证。
- 模型工具结果保持 4000 字符限制；详细截断预算已更新至前后端接口文档。

## 验证

- Agent 教学策略、上下文、语音与测试入口：59 passed，46 subtests passed。
- 后端真实 PostgreSQL 与公开 WebSocket 路由测试：14 passed，1 条现有依赖警告。上游语音使用模拟连接，未做真实麦克风/云端语音回归。
- 无 Run 的编译失败会改变刷新标记，语音能读取具体报错及纠错阶段。
- 四次实际后端模拟沙箱失败形成的结果回执，语音读到失败次数 4、提示等级 3；本地样本读取 30 SQL、约 0.09～0.19 秒，不包含云端语音响应时间。
- 变更标记读取仍为 5 次读取/5 SQL；不产生新的 Run、错误次数或游戏写入。
- 测试入口发现数量校验通过（635 个非联网测试、2 个真实模型测试排除）；这里只核对发现列表，没有宣称本轮跑完全部 635 项。
- Ruff、改动空白检查通过。测试数据库已清理，PostgreSQL 容器恢复测试前停止状态。
