# 已发布 Run / Evidence 读取优化（2026-09-09）

本次仅修改后端结果读取层。前端接口、返回结构、错误详情、错误计数、Agent 路由及写入校验保持原有行为。

已完成的 Run 使用现有 learner handoff 摘要、执行回执和发布回执核对当前结果与完整回复，不再追溯草稿、编译、激活、历史失败和模型调用链。Evidence 仍核对当前错误证据内容及摘要。每次请求使用新数据库快照，没有跨请求缓存。未完成及历史兼容流程继续使用原有读取路径。

## 实测

使用相同的 Godot 提交脚本、真实 Docker 编译与 DS 模型，连续修改并提交三份错误代码。测试在原数据库的临时副本中进行。

| 轮次 | 提交到显示回复：此前→本次 | Run + Evidence SQL：此前→本次 | 两个读取接口合计：此前→本次 |
| --- | --- | --- | --- |
| 1 | 70 → 54 秒 | 449 → 15 | 5.781 → 0.079 秒 |
| 2 | 66 → 49 秒 | 543 → 15 | 6.813 → 0.062 秒 |
| 3（Bug Agent） | 78 → 48 秒 | 637 → 15 | 8.406 → 0.078 秒 |

SQL 减少是这次代码变更的直接收益。端到端测试并非同一时刻的受控性能实验，编译、数据库和模型耗时有波动，不能将总耗时的全部下降都归因于本次修改。Worker 内部 SQL 基本未变，三轮仍约 4,280、4,800、5,585 条；其重复处理和 Docker 编译仍是剩余耗时来源。
