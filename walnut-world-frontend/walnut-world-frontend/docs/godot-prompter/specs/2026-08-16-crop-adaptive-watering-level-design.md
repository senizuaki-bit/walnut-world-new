# 作物适配浇水器第一关前端规格

## 目标

把 v1.3 完整关卡文档转成可运行的 Godot 第一关，并保持“本地教学预演”和“正式 Agent 权威链路”边界清楚。

## 玩家流程

1. 开始界面点击“进入农场”，经遮罩转场进入第一关。
2. 旧 3★ 工具按固定 60 扫描 8 块土地，客观标出 1号漏浇、5号不足、6号多浇；这不是学生失败。
3. 玩家依次比较 1号番茄、6号土豆、5号番茄，覆盖浇1份、跳过、浇2份三种动作。
4. 代码卷轴提供真实题目数据；玩家只操作“交给小核桃”，前端教学预演在一次点击中依次完成本地构建、激活状态切换与世界验证。
5. 本地教学判定覆盖固定目标、差值反向、下标写死、下标错位、分支顺序、分支规则和循环边界。
6. 失败后先显示世界事实，再按 L0—L3 增加透露程度；只有同类失败累计 4 次且玩家主动看完 L3 后，才显示“AI 修改提案”入口。接受 Patch 只生成新草稿，不自动构建、激活或运行。
7. 成功后提供“下一关”“重玩本关”“返回农场”。下一关只展示 5★ 预告，不提前开放双重循环教学。

## 场景责任

- `game_flow.tscn`：开始页、第一关、下一关预告与全屏转场。
- `game_start_screen.tscn`：现有奶油纸张、深绿描边、金色强调的开始界面及补间动画。
- `crop_adaptive_watering_demo.tscn`：关卡状态、2×4 农田、证据卡、代码卷轴与结算。
- `crop_plot_card.tscn`：单块土地的作物、当前/目标湿度、缺口、扫描和结果反馈。

## 权威边界

第一关代码卷轴是前端教学预演，界面必须明确标注，不得把本地源码识别结果称为正式 Run、Evidence 或世界回执。

当前主场景 `game_flow.tscn` 没有实例化 `app_root.tscn`，`crop_adaptive_watering_demo.gd` 也没有调用 Agent Gateway；因此本关尚未接入正式 Agent，只复用了角色资源和本地教学判定。正式 Agent 客户端代码仍保留在 `AppRoot + TaskWorkspace` 链路中。

正式 `TaskWorkspace` 继续负责：

`Draft CAS → Build/Certification → Activation → exact-version Turn → Run/World/Evidence → Interaction → PatchDecision`。

当前发布合同的 `world-presentation-event` 仍是 HARVEST-only。前端不能自行接受 `world.action.watered`，否则会绕过跨仓合同校验。WATER 权威演出要等 Agent/Backend 先发布包含 `amount_ml`、plot/position、完整性哈希与最终快照绑定的新合同版本。

## 视觉与动画原则

- UI 使用 Control + Container + Theme StyleBox；关键布局均预置在场景中。
- 开始界面使用错峰淡入、Back/Elastic 缩放、角色呼吸和按钮悬停补间。
- 关卡使用扫描光、土地卡弹性反馈、代码抽屉滑入、证据卡淡入与结算弹出。
- 水壶图集固定为 4×2、每格 400×480；每帧内容保持透明安全边距，禁止跨格像素。

## 验收

- 主场景先显示开始界面，点击后进入第一关。
- 8 块土地数据与文档一致，正确水量为 `[2,1,1,0,0,2,0,1]`。
- 土地背景保持宽高比并覆盖整个关卡视口；手动阶段按 1、6、5 的顺序持续高亮当前待验证土地。
- 代码抽屉可通过右上角关闭按钮或点击抽屉外区域关闭，只保留“重置”和“交给小核桃”。
- 正确代码客观通过，典型错误稳定分类。
- 结算的下一关与重玩入口可用。
- 新图集八格边缘 alpha 为 0，且不存在相邻帧残片。
- 正式 Agent 离线合同回归保持通过；真实 Gateway 运行仍需显式环境与服务。
