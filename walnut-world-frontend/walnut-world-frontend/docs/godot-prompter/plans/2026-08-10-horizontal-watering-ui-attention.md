# 横向浇水 Demo：儿童注意力与动画反馈改造计划

日期：2026-08-10

> 历史计划：本计划记录第一轮注意力改造。随后已移除横向自动浇水器和调试视图，最终方案以 `docs/superpowers/specs/2026-08-10-horizontal-watering-demo-design.md` 与 `docs/design/verification/loop-magic-completion-audit.md` 为准。

## 目标

让孩子在每个阶段只面对一个主要任务，并能从画面直接理解“我做了什么、代码做了什么、结果发生了什么”。

## 验收标准

1. 手动阶段只突出下一块土地；常驻 HUD 保持紧凑，普通提示为短句并自动消退。
2. 发现重复时使用单一高饱和弹窗，内容以 `0 → 1 → 2 → 3 → 4` 图形关系为主。
3. 进入编程阶段后，代码区与运行结果区固定显示，不提供收起/展开操作。
4. 默认只显示待填写的 `for` 循环、简短运行结果和操作按钮；变量轨迹与统计必须点击“查看调试”后才显示。
5. 示例输出改为“浇 i 号土地中…… / 浇灌完成！”，不再使用 `WATER` 作为儿童可见文案。
6. 手动浇水由小核桃逐块移动完成；自动浇水由横向设备、移动喷头标记和逐块机器反馈完成，小核桃不再代替机器移动。
7. 正确运行后先出现土地变湿、幼苗抬升和“全部发芽”反馈，再显示精简结算卡。
8. 关键界面元素必须是 `.tscn` 中的预置节点；脚本只切换状态与播放补间动画。
9. 场景契约测试、交互流程测试、全量测试和关键状态截图全部通过。

## 执行顺序

1. 调整场景节点与固定布局。
2. 改写教学文案、代码模板和模拟器识别规则。
3. 实现调试信息按需显示、自动设备逐块反馈和分阶段结算。
4. 更新测试并执行 Godot 解析、定向测试、全量测试与视觉截图。

## 自审结论

计划覆盖全部原始反馈，改动范围限定在前端 Demo 与对应测试；不改变后端协议，不回退工作区现有改动，并符合“优先使用预置节点”的项目约束。批准执行。
