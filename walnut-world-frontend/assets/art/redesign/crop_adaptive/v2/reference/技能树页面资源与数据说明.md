## 数据与代码入口

唯一可维护数据是 [skill-tree-data.json](./skill-tree-data.json)。浏览器镜像 [skill-tree-data.js](./skill-tree-data.js) 由 [sync-skill-tree.mjs](./sync-skill-tree.mjs) 机械生成，支持直接双击本地 HTML，不需要跨域读取 JSON。

| 字段 | 作用 |
|---|---|
| nodes | 五个节点的稳定 ID、图标 ID、iconPath、中心位置、尺寸和语义 |
| concepts | 三项能力的标题、短描述和详细解释；树和卡片使用相同 ID |
| states.offer / states.unlocked | 剧情可学习与已解锁的文案、按钮与状态，不能混用 |
| future | 五星名称、后续知识、locked 与 canEnter=false |
| wateringRules | 0—7索引范围、gap定义、30/0边界、2/1份、250ml单位；只是展示契约，不是新的判题器 |
| layout | 1672×941逻辑画布坐标；图标按树形纹理实际圆槽校准 |
| reward | E07大图、标题、说明、三按钮的位置与文案；toolNode指向同一个当前技能 |
| resources | 复用背景、人物、卡片、星星与按钮素材 ID |
| invariants | 禁止空木架、禁止提前解锁、不得把理解点当新课程等约束 |

图标位置按 `treeRect.left + center.x × treeRect.width`、`treeRect.top + center.y × treeRect.height` 计算。`center` 已按最终图校准；不要照抄绘图提示中的预期位置。保持树形图 2:3 比例，先定位底图，再叠加图标，不能分别进行随意拉伸。

[skill-tree.js](./skill-tree.js) 提供两个共用呈现函数：`renderSkillTree` 与 `renderUnlockedToolCard`。`demo.js`、`rebuild.js` 都调用它们，不各自维护一套空树拼装。

## 状态与行为

| 页面 | 4★ | 三张能力卡 | 5★ | 主操作 |
|---|---|---|---|---|
| E03 | 剧情可学习，尚未解锁 | 图标＋理解说明，无完成勾 | 锁定 | 进入清泉工坊 → S03 |
| E10 | 已解锁 | 同一内容＋完成标记 | 仍锁定 | 进入自由状态 → E07 |
| E07 | 展示已获得的同一浇水器 | 不重复铺技能树 | 不因本页解锁 | 原三个按钮保持原流转 |

树上的三个小节点是“理解组成”，不是额外关卡、分数或可跳转课程。五星节点只有功能预告，没有学习热区。正式产品须把 E10 的状态绑定到权威解锁记录，不能从预览中抄出一个永远为真的 unlocked 值。

## 后续 AI 接入步骤

1. 复制 `components` 中被 manifest 引用的文件，保留名字；Godot路径为 `res://assets/art/redesign/crop_adaptive/v2/components/<文件名>.png`。
2. 同时读取 `skill-tree-data.json` 和 `guide-layout.json`，不能只拷树底图。
3. 确保五个圆槽都有对应图标，三个能力卡与中间节点一一对应。
4. E07必须复用 `icon-skill-watering`，不要另找一个不一致的普通水泵。
5. 原生绘制标题、说明与按钮文案；装饰节点忽略鼠标输入；保留原继续、重玩、预告、返回按钮信号。
6. 正式端接入解锁事实，不硬编码 Skill v3、Run次数或验证成功记录。
